# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

BlackInk (formerly FlipLedger; publisher CodeXpirit) is a Kotlin Multiplatform + Compose
Multiplatform app (Android + iOS) for resellers to track device inventory, costs, sales, profit,
invoices, and partner splits. It is **online-backed by Supabase** (Auth + Postgres/PostgREST +
Edge Functions) with **Stripe** subscriptions; there is no offline/durable local store — repositories
keep in-memory `StateFlow` caches.

Package / applicationId / iOS bundle id: **`com.blackink.app`**. Deep-link scheme: **`blackink://`**.

## Commands

Requires **JDK 17** (Gradle needs `javac`, not just a JRE). On this machine:
```bash
export JAVA_HOME=/opt/homebrew/opt/openjdk@17/libexec/openjdk.jdk/Contents/Home
```

- **Shared tests (all):** `./gradlew :composeApp:allTests`
- **Shared tests (Android/JVM only, faster):** `./gradlew :composeApp:testDebugUnitTest`
- **Single test class:** `./gradlew :composeApp:testDebugUnitTest --tests "com.blackink.app.MoneyTest"`
- **Android debug APK:** `./gradlew :androidApp:assembleDebug` → `androidApp/build/outputs/apk/debug/androidApp-debug.apk`
- **Install/run on device:** `adb install -r <apk>` then `adb shell monkey -p com.blackink.app -c android.intent.category.LAUNCHER 1`
- **Release AAB:** `./gradlew :androidApp:bundleRelease` (signed only if `keystore.properties` exists; otherwise unsigned)
- **iOS:** `cd iosApp && xcodegen generate` then open `iosApp.xcodeproj` in Xcode and run — **or** `xcodebuild -project iosApp.xcodeproj -scheme iosApp -sdk iphonesimulator -destination 'generic/platform=iOS Simulator' -configuration Debug build`. The Xcode build phase compiles the Kotlin framework via `./gradlew :composeApp:embedAndSignAppleFrameworkForXcode`.
- **Edge functions:** `supabase functions deploy <name>` · **DB migrations:** `supabase db push`

There is no configured linter/formatter (no ktlint/detekt).

## Module layout

- **`composeApp`** — all shared code: Compose UI, ViewModels, domain, data. This is where ~everything lives.
- **`androidApp`** — thin Android host (`MainActivity`, `BlackInkApplication`) + native Firebase/Play/notification integrations that install the shared facades.
- **`iosApp`** — SwiftUI host. **Generated by XcodeGen from `iosApp/project.yml`** — edit `project.yml` (not the `.pbxproj`) and re-run `xcodegen generate` after adding files or dependencies. Firebase is pulled via Swift Package Manager here.
- **`supabase/`** — `migrations/` (schema + RLS + RPCs) and `functions/` (Deno/TypeScript Edge Functions).

## Architecture (the parts that span files)

**Clean Architecture + MVVM inside `composeApp/src/commonMain/kotlin/com/blackink/app/`:**
`presentation/` (screens + `*ViewModel` extending `BaseViewModel`) → `domain/` (models, `repository/` interfaces, `usecase/`) → `data/` (repository impls, `remote/` Supabase) → `core/`.

**DI is Koin.** `di/InitKoin.kt` aggregates four modules: `platformModule()` (expect/actual — `ObservableSettings`, dispatchers, etc.), `coreModule` (Supabase client + repository singletons), `domainModule` (use-case factories), `presentationModule` (`Navigator` + `WizardStore` as singletons, ViewModels as factories). Screens get their ViewModel via `rememberViewModel<T>()`, which pulls from Koin and cancels its scope on dispose.

**Navigation is a custom stack `Navigator`** (`presentation/navigation/`), **not Voyager** (Voyager appears in the version catalog but is unused). `Route` is a sealed interface; **`App.kt` → `AppNavHost` is the single `when (route)` that maps every route to a screen** and wires each screen's callbacks to navigator ops — screens never touch the `Navigator` directly. **Post-auth navigation is reactive, not imperative:** `AppViewModel` maps `authRepository.sessionState` (+ onboarding flag) to a `StartDestination`, and `App.kt`'s `LaunchedEffect(start)` does `resetTo(...)`. When adding an auth/entry screen, remember it must be in the `atEntry` set in that effect or routing won't fire.

**Platform features are reached from shared code through installed facades**, not expect/actual, for anything that would otherwise force CocoaPods or a Kotlin bump. The pattern (see `core/telemetry/Telemetry.kt`, `core/notifications/Notifier.kt`, `core/review/ReviewPrompter.kt`): a commonMain `interface` + `NoOp` default + a mutable `XProvider.instance` holder, **installed at startup** from `BlackInkApplication.onCreate` (Android) and `iOSApp.init()` (iOS, in Swift). A few genuinely platform things do use `expect/actual` instead (`platformModule`, `rememberCsvExporter`, `rememberInvoicePdfExporter`, `SocialAuthProvider`, `CheckoutBrowser`).

**Supabase data layer:** Auth uses email/password with **email-OTP signup verification** (`verifyEmailOtp`, plus Google/Apple `IDToken`); Postgrest for tables; Functions for Stripe/account operations. RLS enforces per-user access via `auth.uid()`, and tables `ON DELETE CASCADE` from `auth.users`. Money is stored as **`Long` cents**; dates are **ISO `yyyy-MM-dd` strings**. `SupabaseConfig.kt` holds the public URL + anon key; the service-role/Stripe/Resend keys live **only in Supabase secrets**, never in the app.

**Edge Functions** (`supabase/functions/`, Deno + TS, shared helpers in `_shared/`): `create-checkout-session`, `create-portal-session`, `stripe-webhook` (+ `stripe-return`), `send-welcome-email`, `delete-account`. Stripe/email keys come from Supabase secrets; the webhook verifies Stripe signatures.

**Error UX convention:** top-level/server errors surface through a **single global top banner** — call `UiErrorEffect(state.error)` in a screen and it feeds `core/ui/UiBanner`, rendered once by `ErrorBannerHost` at the app root. **Field-level** validation stays inline next to the input. Do not render top-level errors inline at the bottom of scrollable content.

## Constraints that will bite you

- **Do not bump the Kotlin toolchain.** Kotlin **2.1.0** / Compose **1.7.3** / AGP **8.5.2** / supabase-kt **3.0.3** are pinned together: the supabase-kt iOS klib ABI is matched to this Kotlin version, and the Firebase telemetry is done via native SDKs + facades specifically to avoid a KMP wrapper that would force a Kotlin bump. A Kotlin bump risks the iOS build.
- `compileSdk`/`targetSdk` are **35** via `android.suppressUnsupportedCompileSdk=35` in `gradle.properties` (AGP 8.5.2's tested max is 34) — this is intentional for Play's targetSdk requirement.
- Firebase Gradle plugins are applied **only when `androidApp/google-services.json` exists**; without it the app still builds and telemetry falls back to no-op. The `google-services.json` / `GoogleService-Info.plist` are client-safe and committed.
- Release signing reads a **gitignored `keystore.properties`**; absent → the release build is unsigned (fine for verifying it compiles, not for Play).
